# Sisyphus

Sisyphus 是一个基于 Electron、React 和 Go 的桌面 AI 智能体应用，支持多模型对话、本地文件分析、知识库问答和提示词工作流。

React 负责交互界面，Electron 负责桌面能力与进程管理，Go 运行时负责模型调用和工具执行。

## 功能

- **多模型对话**：支持配置 OpenAI 兼容接口，内置 DeepSeek、MiniMax、GLM 等供应商配置，可设置 API Key、接口地址和模型。
- **本地文件助手**：在用户选择的工作目录中列出目录、读取文本文件、搜索内容，并结合模型完成分析。
- **知识库问答**：将笔记和文档在本地生成向量，通过检索相关片段为模型提供参考资料。
- **自定义助手**：通过名称和系统提示词配置不同用途的助手。
- **提示词工作流**：支持带变量的提示词模板和顺序执行的提示词队列，可导出 Markdown 结果。
- **会话管理**：保存历史对话，支持切换、删除会话及添加文本附件。
- **任务控制**：展示工具执行状态，支持取消任务、超时控制和执行轮数限制。

## 系统架构

应用采用 Electron 主进程、Preload 桥接层、渲染进程与 Go 子进程协作的架构。

```text
┌─────────────────────────────────────┐
│ React 渲染进程                       │
│ 聊天界面 · 知识库 · 助手 · 工作流      │
│ Zustand 状态管理                     │
└──────────────────┬──────────────────┘
                   │ Preload / IPC
┌──────────────────▼──────────────────┐
│ Electron 主进程                      │
│ 窗口管理 · 原生对话框 · 目录授权        │
│ 子进程管理 · 请求与事件转发             │
└──────────────────┬──────────────────┘
                   │ stdin / stdout
                   │ JSON Lines
┌──────────────────▼──────────────────┐
│ Go 智能体运行时                      │
│ 模型调用 · 工具执行 · 任务控制          │
└─────────┬────────────────┬──────────┘
          │ HTTP           │ 只读访问
          ▼                ▼
   模型供应商 API      用户授权的工作目录
```

### 各层职责

| 模块 | 目录 | 职责 |
| --- | --- | --- |
| 渲染进程 | `src/renderer/` | 页面交互、会话管理、模型配置、本地知识检索和任务状态展示 |
| Preload | `src/preload/` | 通过 `contextBridge` 向界面暴露 IPC 调用与事件订阅接口 |
| 主进程 | `src/main/` | 管理窗口、文件对话框、工作目录授权和 Go 子进程；处理模型列表及单次聊天接口 |
| Go 运行时 | `agent/` | 调用模型接口、执行文件工具、管理执行循环、取消和超时 |
| 共享类型 | `src/shared/` | 定义跨进程使用的事件类型 |

Go 运行时由 Electron 启动，不需要单独部署服务，也不监听本地端口。任务和事件通过逐行 JSON 传递，使用 `requestId` 关联请求与响应。

### 智能体执行流程

1. 界面组装用户消息、会话上下文、助手提示词和知识库检索结果。
2. Electron 将任务与已授权的工作目录传递给 Go 运行时。
3. Go 请求模型；如果模型返回工具调用，则执行工具并将结果加入上下文。
4. 重复模型调用与工具执行，直到获得最终回答或达到执行限制。
5. 工具状态和任务结果经 Electron 返回界面，最终回答保存到对应会话。

未选择工作目录时，任务不启用文件工具。模型请求采用非流式方式，工具状态实时返回，最终回答完整返回。

### 文件工具

| 工具 | 用途 |
| --- | --- |
| `list_directory` | 列出指定目录中的文件和子目录 |
| `read_file` | 读取 UTF-8 文本文件 |
| `search_text` | 在目录中按字面量搜索文本 |

文件工具使用 Go `os.OpenRoot` 限制访问范围，拒绝路径越界和指向工作目录外的符号链接。工具不提供文件写入或 Shell 执行能力。

### 状态与数据

- **应用配置**：模型配置、用户资料和界面偏好由 `appStore` 管理，选定字段保存到 localStorage。
- **会话数据**：`conversationStore` 保存会话及消息，任务结果写入发起请求的会话。
- **运行状态**：`chatStore` 和 `agentStore` 管理临时响应、任务 ID、工具状态和工作目录，不持久化。
- **助手与工作流**：分别由 `assistantStore` 和 `skillStore` 管理并持久化。
- **知识库**：文档分块后在本地生成向量，通过余弦相似度检索相关内容，再注入模型上下文。

## 快速开始

### 环境要求

- Node.js 18+ 和 npm
- Go 1.24+

Go 仅在开发和构建时需要，安装包中包含运行时可执行文件。

### 安装与启动

```bash
npm install
npm run dev
```

启动命令会先构建 Go 运行时，再启动 Electron 开发环境。渲染进程支持热更新；修改 Go、主进程或 Preload 后需要重新启动应用。

### 使用方式

1. 在设置中填写模型供应商的 API Key、接口地址和模型。
2. 直接发送消息进行对话，或选择工作目录启用文件助手。
3. 输入任务，例如“阅读 README.md，总结项目结构”。
4. 查看工具执行状态，必要时点击“停止”取消任务。

文件助手要求模型和接口支持 OpenAI 兼容的 `tools` / `tool_calls`。工作目录授权仅在当前窗口会话中有效，刷新或重启后需重新选择。

## 开发与构建

| 命令 | 说明 |
| --- | --- |
| `npm run dev` | 构建 Go 运行时并启动开发环境 |
| `npm run build:agent` | 单独构建 Go 运行时 |
| `npm run typecheck` | 检查主进程和前端 TypeScript 类型 |
| `npm run test:agent` | 运行 Go 测试及竞态检测 |
| `npm run build` | 构建 Go 运行时和 Electron 应用 |
| `npm run package` | 构建应用并生成安装包 |

Go 构建产物位于 `build/agent/`，Electron 构建产物位于 `out/`，安装包输出到 `dist/`。打包配置包含 Windows NSIS、macOS DMG 和 Linux AppImage 目标。

跨平台打包时，Go 的 `GOOS` / `GOARCH` 必须与 Electron 目标平台和架构一致。协议细节、测试要求及跨平台构建方式见 [Go 运行时说明](agent/README.md)。

## 使用边界

- 同一时刻执行一个智能体任务，最多请求模型 10 轮，任务总超时为 3 分钟。
- 单文件读取上限为 64 KiB；目录列表与文本搜索也有结果数量和扫描范围限制。
- 文件内容和知识库检索结果可能发送到配置的模型供应商，请勿授权或上传包含密钥、凭证等敏感信息的资料。
- 工作目录限制不是完整的操作系统沙箱；应用不提供逐文件审批或敏感内容自动检测。
